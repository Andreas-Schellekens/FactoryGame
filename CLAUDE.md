# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — start the Vite dev server with hot reload
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the production build locally
- `npm run voice` — record DELTA's voice lines with ElevenLabs (`scripts/voice.mjs`; `-- --dry` lists what it would do; needs a `.env`, see `.env.example`)

There is no test runner, linter, or formatter configured.

## Overview

**Protocol: Selene** — a Factorio-style factory game with a story campaign (vanilla JS + Vite), rendered in 2.5D with [Three.js](https://threejs.org): real 3D models under a fixed-angle isometric orthographic camera. Models are CC0 packs by Kenney (see `CREDITS.md`). The player builds a production chain on a grid: **ore node → extractor → belts → smelter → belts → assembler → belts → Dispatch Pad** (the `sink` machine type). The pad pays credits for sellable goods; credits fund more machines and tier upgrades. Deliveries also advance the **campaign**: five Protocol: Selene phases (build a cannon to "save Earth from the falling Moon"), each requiring item deliveries and unlocking buildings. An AI guide, **DELTA**, narrates, teaches and drives the satirical plot (*NILE*, the Network for Infrastructure, Logistics & Engineering, is slowly revealed to be *NIHIL*, the Network for Infrastructure, Heavy Industry & Logistics). Story bible and iteration roadmap: `docs/DESIGN.md`. All in-game text is English.

The production chain (all defined in `grid.js`):
- Three ore deposits sit on the map as terrain (`cell.resource`): `ironOre`, `copperOre`, `coalOre`.
- **Extractor** (must be placed on an ore node) mines that ore.
- **Smelter** turns `ironOre→ironIngot`, `copperOre→copperIngot`.
- **Assembler** runs the first satisfiable recipe in the `ASSEMBLE` list: `1 ironIngot + 1 copperIngot → circuit`, `2 circuit + 1 ironIngot → advancedCircuit` (research-gated), `2 circuit → research`.
- **Generator** burns `coalOre` from its buffer to feed the global power network (see below).
- **Lab** consumes `research` items and banks `RESEARCH_PER_ITEM` research points (no item output).
- **Sink / Dispatch Pad** accepts anything in `SINK_VALUE` (ingots pay a little, `circuit` at `PRODUCT_REWARD`, `advancedCircuit` at a premium) plus whatever the active campaign phase requires, pays per type, and credits the phase.

Two routing machines move items without transforming them: a **splitter** (1 input on the back → 3 outputs: straight ahead + both perpendiculars, round-robin) and a **merger** (3 inputs: back + both perpendiculars → 1 output straight ahead). `dir` is the primary flow axis for both.

**Power** is a global network, not an item: each tick supply (`BASE_POWER_SUPPLY` "starter grid" + `POWER_PER_GENERATOR` per fueled generator) is compared to the demand of powered machines (`POWER_DRAW`: smelter, assembler, lab) that currently want to work; the ratio is clamped to a `throttle ∈ [0,1]` that scales their progress, so undersupply slows the factory smoothly instead of stalling it. Extractors are deliberately unpowered so the bootstrap chain can't brown itself out.

The **campaign** (`campaign.js`) is the main progression layer: you start with belt/extractor/smelter (`STARTING_BUILDINGS`); each completed phase in `PHASES` unlocks more (assembler/splitter/merger → lab → generator). Completing the last phase ends the game (the ending cinematic and mission report, then sandbox).

**Research** is the secondary layer: assembler-crafted `research` items go into a lab, points buy permanent unlocks via `unlockTech(id)` — `fastBelts` (movers phase runs twice per tick), `advancedProduct` (enables the advancedCircuit recipe), `tier4` (raises the upgrade cap from `MAX_TIER - 1` to `MAX_TIER`). Costs live in `config.js` `TECH_COST`. (Buildings are never research-gated.)

An **order** system ("Priority Requests", from phase 2 on) layers a timed bonus on top: a demand for N products within M ticks pays a one-off reward on completion (see `grid.js` order state and `config.js` `ORDER_*`).

Some older comments may be in Dutch.

## Architecture

The simulation (`grid.js`) is the source of truth and has **no knowledge of Three.js or the DOM**. Everything else reacts to it. Each `src/` file has one job:

### `src/grid.js` — simulation core
- Owns the `grid` (2D array of `{ machine, item, resource }` cells) and the exported `score` (money). `score` is a live ES-module binding — other modules `import { score }` and read the current value directly. Same pattern for `tickCount` (the monotonic sim clock, advanced once per tick), the `order` object, the `power` network state (`{ supply, demand, throttle }`, recomputed every tick, never saved), the `research` state (`{ points, unlocked: { fastBelts, advancedProduct, tier4 } }`, saved), the campaign `project` state (`{ phase, delivered, complete }`, saved — `phase` indexes `PHASES`, `delivered` counts the active phase's required items) and lifetime `stats` (`{ produced, delivered, researchEarned }`, saved; read by the story director) — all mutated in place.
- A **machine is an object**: `{ type, dir, tier, buffer, pendingOutput, progress, produces?, toggle?, fuelTicks? }`. `type` ∈ `belt | splitter | merger | extractor | smelter | assembler | generator | lab | sink`. `dir` ∈ `right | down | left | up` (output / primary-flow direction). `buffer` holds input-item counts (capped at `BUFFER_CAP`); items inside a buffer have **no sprite** (they were `consume`d on entry). `toggle` is the round-robin cursor for splitters/mergers; `fuelTicks` is the generator's remaining burn. Tier (1–`MAX_TIER`) scales processing speed via `PROCESS_TICKS`; `progress` may be **fractional** on powered machines (it advances by `power.throttle`).
- `updateFactoryLogic()` advances one tick and **returns `FactoryEvent`s** (`spawn` / `move` / `consume`). It first does `tickCount++`. Phases run in a fixed order: (1) sinks consume their item, pay `SINK_VALUE`, credit the active order, `project.delivered` and `stats.delivered`, then `checkPhaseComplete()` advances `project.phase` once every requirement is met (the `phase` bump is the only completion signal) — then the order resolves (complete pays `order.reward`, or fail past the deadline) → (2) processors (incl. generator and lab) absorb their input-slot item into their buffer → (3) **movers** (belts, splitters, mergers) relocate items, reverse scan — the whole phase runs **twice** when `fastBelts` is unlocked → (3.5) **power**: generators burn coal (one `coalOre` lasts `GENERATOR_FUEL_TICKS`) into `power.supply`, powered machines with a runnable recipe add their `POWER_DRAW` to `power.demand`, and `power.throttle = clamp(supply/demand, 0, 1)` → (4) processors advance `progress` by `throttle` (unpowered: by 1) and eject the result (counted in `stats.produced` when crafted, even if the output is blocked); a completed **lab** recipe adds `RESEARCH_PER_ITEM` to `research.points` instead of ejecting → (5) extractors mine. Ejection/mining happen *after* movers so a newly produced item waits a tick before moving (no same-tick double-hop). The event list is the simulation's only output channel; the renderer reacts to it rather than diffing the grid.
- Splitters push their item to one of `splitterOutputs(dir)` (`[dir, ...PERP[dir]]`) round-robin; mergers push their held item forward then pull from one of `mergerInputs(dir)` (`[OPPOSITE[dir], ...PERP[dir]]`) — pull-only (`cellAccepts` is false for a merger), gated by `outputsToward()` so they only take from neighbours aimed at them. `toggle` advances past the side actually used so a blocked side can't skew the balance.
- `cellAccepts(cell, itemType)` is the single gate for all item transfer (belts, splitters, machine inputs, sink): it enforces empty slot, recipe match (assembler inputs are filtered to recipes whose `tech` gate is unlocked), buffer cap, coal-only generator, research-only lab, and the sink's `sinkAccepts` (`SINK_VALUE` ∪ active phase requirements). Recipes live in the `SMELT` table, the `ASSEMBLE` recipe list (entries may carry a `tech` unlock id), `LAB_RECIPE` (output `null` = points), and `recipeFor()`.
- Build/economy API: `canBuildMachine` / `buildMachine` (extractor requires `cell.resource`; every type must pass `isBuildingUnlocked(type)`, derived from `project.phase`), `placeBelt` (drag-laying), `removeMachine` (refunds the base `MACHINE_COST` so the economy can't soft-lock; returns `consume` events for any destroyed in-transit item; the sink is protected), `canUpgrade` / `upgradeMachine` / `upgradeCost` (caps at `MAX_TIER - 1` until the `tier4` unlock), and `machineProgressFraction` (for the renderer's progress bars).
- Research API: `research` (live state) and `unlockTech(id)` — checks/spends points against `TECH_COST` and flips the permanent `unlocked` flag. The HUD pulls both via `getState()`.
- Order API: `order` (state: `active`, `status` ∈ `none | active | completed | failed`, `target`, `reward`, `delivered`, `startTick`, `deadlineTick`) and `startOrder({ target, ticks, reward })` — grid.js counts deliveries and pays the reward; *which* order to issue (difficulty/cadence) is policy chosen in `main.js`. The `status` flip is the only completion/failure signal — the HUD polls it via `getState()`.
- Campaign API: `project`, `stats`, `isBuildingUnlocked(type)`, `currentPhase()`.
- Ports API (read-only, mirrors the transfer rules; feeds the renderer's port arrows and the inspector): `portsFor(type, dir)` → `{ in: [sides], out: [sides] }` (processors: in = back + sides, out = front; generator/lab/pad: in on all sides, no out; extractor: out only; splitter: in back, out front + sides; merger: in back + sides, out front; belts: none), `machinePorts(x, y, type?, dir?)` → `[{ side, kind: 'in'|'out', connected, blocked }]` for a placed machine or a build preview (`connected`: a neighbour actually takes from / sends into that side; `blocked`: a finished product is stuck in `pendingOutput`), and `machineIO(type)` → `{ takes, makes }` item types.
- Terrain: `initGrid()` also marks the `CANNON_AREA` cells `blocked` (the reserved Selene construction site): `canBuildMachine`/`placeBelt` refuse them and `loadState` skips saved machines there. `cellHash(x, y)` is the deterministic per-cell random used for map and decor layout.
- Save/load API: `serialize()` returns a plain JSON-able snapshot (version `SAVE_VERSION` = 2, `score`, `tickCount`, `order`, `research`, `project`, `stats`, and only the non-empty cells — terrain is recreated by `initGrid()`); `loadState(data)` rebuilds the grid (re-`initGrid()` then overlays saved machines onto `makeMachine` defaults), resets `research`/`project`/`stats` to defaults before overlaying the saved values, and **returns `spawn` events for in-transit items only** — buffer contents and `pendingOutput` have no sprite, so they are never spawned. `power` is not saved (recomputed each tick); generator fuel persists via the machine's `fuelTicks`. Returns `null` on missing/version-mismatched data.

### `src/renderer.js` — the 3D view (Three.js)
- `await createRenderer(container, { onProgress })` loads the models (`assets.js`), builds the scene (lights, environment, ore nodes) and returns `{ canvas, rig, applyEvents, tweenItems, draw, reset, pickCell, projectCell }`. World mapping: cell `(x, y)` is centred on world `(x + 0.5, 0, y + 0.5)`; grid "down" (+y) is world +z; model forward is +z, so `dir` → yaw via `YAW`.
- **Machine views** are synced from the grid every frame (`syncMachines`): each cell's view is keyed by a signature (`type|dir|beltShape`) plus the machine object's identity, and rebuilt only when that changes. `buildView(m, …)` composes Kenney models per type (belt / corner belt, router cross + arrows for splitter/merger, extractor frame + piston over its ore rock, smelter + chimney + glowing mouth, assembler + cog, lab + dish, generator cooling tower + glow, Dispatch Pad platform + a compact drop-zone marker: a short light cone, a bobbing downward chevron sprite and a pulsing ring) and a status cluster of sprites (progress bar, tier dots, power pip). Corner belts use the native `conveyor-stripe-corner` (connects the −x and +z sides) rotated by `cornerFit()`.
- **Belt motion:** a shared chevron texture on flat ribbons (`ribbon()`: v runs along the centreline, so straight and curved belts scroll at the same density) whose offset advances one cell per tick (two with Express Belts).
- **Items:** `items` (`Map<itemId, { obj, anim }>`) bridges simulation items to meshes from `createItemMesh`. `applyEvents(events, tickMs)` creates/tweens/destroys them — a second `move` in one batch (fastBelts) extends the tween; heights come from the cell's machine (`surfaceY`). `reset()` drops all item meshes (used on load).
- An internal animation clock (`animMs`, scaled by `state.speed`, frozen while paused) drives pistons, cogs, dishes, smelter glow, generator glow and the pad beacon off `machineProgressFraction` and `power.throttle`. Smelters puff smoke from their chimney and fueled generators steam (`effects.smoke`); furnace mouths and generator tops carry additive halo sprites (fake bloom).
- **Phase mood:** `MOODS` (per phases completed) sets hemisphere/sun/rim light colours, intensities, the sun's direction, exposure and environment intensity — sunny morning → afternoon → golden hour → dusk → red night → blood red. `applyMood()` eases toward it (snaps on load); the pad beacon turns red at phase ≥ 4. `draw()` forwards phase changes to `env.setPhase` / `cannon.setPhase` (a single step forward animates, anything else is instant).
- **Juice:** new machines pop in (`easeOutBack`) with a dust puff and (non-conveyors) a small camera shake, demolished ones shrink and sink with a puff (`dying`), upgrades sparkle and bounce, deliveries float "+N credits" over the pad (batched per 450 ms), and a completed phase shakes and punches the camera. `floatAt(x, y, text, color)` floats text over a cell (main.js: build/upgrade cost, demolish refund). A `quiet` flag (first sync, and after `reset()` on load) builds views without juice. Every built cell except conveyors (belt/splitter/merger — `CONVEYORS`; those only hide the flowers via `env.coverCell`) is paved (`env.paveCell`), smelters/generators also scorch (`env.scorch`); `saveVisual()`/`loadVisual()` persist the paving. `stats()` returns the last frame's draw calls/triangles.
- **Overlay:** cursor outline, a build ghost (the real model in a green/red ghost material, cached per tool+dir inside a wrapper group that pops in on a tool change, turns from the old direction on R, and wiggles on `nudgeGhost()` when a build is refused), a tinted box for erase/upgrade, and pulsing focus rings around `state.focus` (the active objective's target: an ore type or `'sink'`; only the field nearest the pad is ringed). All hidden while `state.cinematic`.
- **Ports:** small flat arrows at machine edges (instanced, drawn over the world): teal = input, orange = output, bright when `machinePorts` says something is hooked up, dim when not, red and pulsing when the output is blocked. Shown for every machine while a build tool is held, always for the hovered machine and for the build ghost (its would-be connections), and blocked outputs always. An output and the neighbouring input line up into a two-arrow chain across the edge. Refreshed every ~120 ms.
- **Ending API** (driven by the HUD's timeline): `frameCannon({ radius, top })` cuts the camera to the cannon, finds a patch of clear sky in the upper frame by raycasting against the world (the sky only shows beyond the valley's far edge in this view), returns it as the Moon's page point and swivels the turret to aim there; `chargeCannon(level)`, `fireCannon()` (shake + punch), `muzzlePage(along)`, `releaseCinematic()`.
- `pickCell(clientX, clientY)` raycasts onto the ground plane; `projectCell(x, y)` gives a cell centre's page coordinates (used by tests).
- `icons`: build-menu pictures (`{ [machineType]: PNG data URL }`), rendered once at startup by `renderIcons` from the real machine views (game camera angle, output to the lower right; the belt carries ore, the extractor stands on its crystal), plus the edit tools as small 3D props in the same materials (`TOOL_PROPS`: `upgrade` = a machine with two gold chevrons rising out of it, `erase` = a sledgehammer landing on a breaking crate, `rotate` = a belt with a clockwise teal arrow round it; framed by their silhouette rather than their bounding sphere). They are drawn by the main renderer into a corner of its own canvas before the first frame and copied out in the same task: no second WebGL context, and the same tone mapping as the game. main.js passes them to the HUD.

### `src/assets.js` — models + item meshes
- `MANIFEST` maps keys to Kenney GLBs in `public/assets/kenney/` with a `fit` (larger footprint side, in cells), optional `yaw` and `tint` (recolour by material name — Space/Nature kit materials are named `rock`, `crystal`, `stone`, `grass`, `metal…`). `loadAssets()` normalises each model (centred, standing on y = 0, scaled to `fit`, shadows on) and forces non-metal materials to `metalness 0` (glTF defaults to 1, which renders flat-colour models black). `get(key)` returns a clone sharing geometry/materials. `tintTemplate()` recolours named materials (ore nodes use `ORE_TINT`). `createItemMesh(type)` builds the procedural item meshes (ore chunks, ingot bars, circuit boards, research flasks).

### `src/environment.js` — the valley and its decay
- `buildEnvironment(scene, assets, effects)` → `{ setPhase(p, instant), update(dt), paveCell, scorch, savePaved, loadPaved }`. A green valley (`docs/DESIGN.md` "Visual arc"): a greyscale ground texture tinted per phase (`LAND`), a faint build grid, a transparent paving canvas over the buildable area (cannon-site gravel, concrete under built cells, scorch marks), merged cliff walls, the Steward's camp (tents, campfire with halo + smoke; goes out at the reveal), a farm, a pond, a forest and NILE's compound on the east rim. Per phase: trees switch normal → `_fall` → `_dark` and get felled (they tip over, then become stumps) by a per-tree `fellPhase`; phase-gated props (`addProp(key, x, z, min, max)`) fade in/out — flowers vanish, mushrooms appear at dusk, crops die; compound buildings (`BIG_BY_PHASE`) pop in on lattice slots nearest the pad first; floodlights light up from golden hour; shared nature material colours (grass, leaves, dirt) ease toward `LAND`. Small props cast no shadows (`NO_SHADOW`) and static scenery is merged (`mergeStatic`) to keep draw calls down. The sky is CSS behind the canvas.

### `src/cannon.js` — Protocol: Selene on the map
- `buildCannon(scene, assets, effects, CANNON_AREA)` → `{ setPhase(done, instant), update(dt, timeMs), muzzle(along), pivot(), directionAt(yaw), aim(yaw, instant), charge(level), fire() }`. Five parts, parallel to campaign `PHASES`, built from its own geometry in the HUD's palette (gunmetal, steel, signal-orange accents that turn alarm red after the reveal, a paper-white dish, cyan capacitor glow): the foundation + launch deck; a tracking dish on a mast (back corner); a bank of three capacitors with cables into the turret (right edge); the turret (fixed base ring, a turntable `yawGroup` that swivels, cheek plates holding the barrel on an axle, `barrelPivot` at 50° elevation, the recoiling `barrelGroup` with breech block, tube, rails, bands and muzzle brake); and the charge rings + muzzle glow (their own part, mirrored onto the barrel's transform each frame by `syncRings`). finished parts solid, the current one a **blueprint hologram** (`EdgesGeometry` lines + a faint normal-blended fill + a scan line sweeping up; blue, red after the reveal), later ones hidden. The **construction site** around it: before the foundation, cones and hazard tape around the dig; from then on a painted launch deck (the kit platform retinted to matte concrete with a signal-orange rim, plus a canvas decal: hazard-striped border, NILE's delta mark and "SELENE · PAD 01", repainted red with NIHIL's flat line after the reveal), procedural scaffolding (poles, mustard rails, plank walkways) wrapped around the part being built (phases 1–3), crates, a swinging crane and blinking beacons (`site*` models in the manifest); the dressing is cleared away when the cannon is complete. Completing a phase materialises the part with sparks and dust; when all are done the rings hum. For the ending the turret swivels (`aim`), `charge` builds glow and sparks along the barrel, and `fire` recoils the barrel with a muzzle flash, a shockwave ring over the ground, sparks, dust and smoke; afterwards it stays spent (dim rings). A save loaded after the ending shows it spent.

### `src/effects.js` — particles and glows
- `createEffects(scene)` → `{ puff, sparkle, smoke, floatText, update(dt, centre, phase, bounds) }`: a pooled sprite particle system (dust, additive sparks, smoke/steam), floating text sprites, butterflies over the meadow (fewer each phase, none from dusk), falling ash (phase ≥ 3) and rising embers (phase ≥ 4) spawned around the camera target. `haloSprite(color, size)` makes an additive glow sprite. Effects run on real time (they keep going while paused).

### `src/camera.js` — isometric camera rig
- `createCameraRig(bounds)`: an orthographic camera orbiting a ground target at a fixed 38° elevation. `panPixels` (drag) + `endPan()` (the view glides on after a middle-drag), `panBy` (keys), `zoomBy`, `rotate(steps)` (90° steps), `focusOn`, `resize`, `target` (live look-at point), and `update(dt)` which eases toward the goal each frame. Juice: `shake(amount)` (trauma that decays; offset + a little roll, strength trauma²) and `punch(amount)` (a zoom kick that springs back). Cinematics: `snap({ x, z, zoom, azimuth })` cuts without easing (default view direction), `shiftPixels(dx, dy, h, { snap })` moves the view by a screen delta.

### `src/gameLoop.js` — the loop
- `startGameLoop(renderer, state, onFrame, onEvents)` runs a **fixed-timestep tick on a `requestAnimationFrame` loop**: clamps the frame time to 0–100 ms (the first frame's timestamp can predate the loop's start after a long startup task, and a negative dt would make every eased value explode), accumulates `dt * state.speed` and calls `updateFactoryLogic()` once per `1000 / TICK_RATE` ms (catching up at most 8 ticks per frame, then dropping the backlog), feeding events to `renderer.applyEvents` with a tween length of one tick of wall time, and to `onEvents` (sound). Each frame then runs `onFrame(dt)` (HUD, director, key-panning) and `renderer.draw(state, dt)`.

### `src/campaign.js` — campaign skeleton (sim data)
- `STARTING_BUILDINGS`, `PHASES` (`{ id, requires: {item: n}, unlocks: [buildingType] }`) and `unlockPhaseOf(type)`. Pure data read by `grid.js`; no player-facing text.

### `src/story.js` — all player-facing text
- Names (`GAME_TITLE`, `BRAND` — `nile`/`nihil`, each `{ name, full, motto, byline }` — with `brandFor(phase)`/`brandName(phase)` (NIHIL from phase index 4, the reveal), `ITEM_NAMES`, `BUILDING_NAMES`, `BUILDING_DESC`, `TECH_TEXT`, `PHASE_TEXT` parallel to `PHASES`), DELTA's script `BEATS` (`{ id, when(w), lines, banner? }`), per-phase `OBJECTIVES` (`{ id, text, done(w), hint, focus? }`), `AMBIENT` chatter, order `REACTIONS`, `ENDING` (its lines, plus the cinematic's caption/status texts, the Moon+ billboard and the mission report's strings). Lines are `{ who: 'delta'|'nile'|'memo', text, mood? }` (mood: `happy|glitch|sinister`). Predicates read the world snapshot `w` built by `main.js` `snapshot()` (field list at the top of the file).

### `src/director.js` — story director
- `createDirector({ say, banner, ending, isBusy })` → `{ update(w), objectives(), ended(), save(), load(data, tick) }`. No DOM/Three.js. `update` (called ~5×/s) shows phase banners immediately, then plays **one beat at a time, only when the comms panel is idle** (`isBusy()`), re-checking `when(w)` at that moment so a tutorial step the player already did is skipped rather than arriving late. Also: sticky objective ticks, hints for an objective left open `HINT_DELAY` ticks, order reactions, ambient lines, and the one-shot ending trigger when `w.complete`. Timings are in sim ticks, so pausing pauses DELTA. Its `flags` set is persisted in the save under `story`.

### Sound (`src/audio.js` + `synth.js`, `music.js`, `sfx.js`, `ambience.js`, `voiceLines.js`)
All sound is **synthesized with the Web Audio API** (no sample files), so music, effects and ambience share one sound world and follow the arc. None of it knows the simulation or the DOM (apart from `<audio>` elements for voice clips).
- `synth.js` — the instruments, as plain functions `(ctx, out, t, …)` that schedule their nodes at absolute context time: `tine` (kalimba/marimba), `bell` (FM), `pad`, `bass`, `noise` (filtered bursts), `kick`, `metal` (inharmonic FM clank), `blip`, `sweep`, `chirp` (birds), `cricket`; plus `noiseBuffer` and `impulseResponse` (a synthetic reverb room). They work on an `OfflineAudioContext` too.
- `music.js` — the procedural score. `SCORE` has one mood per phases-completed (0–4) plus the aftermath (5); all share D as tonal centre while the **mode darkens one note per milestone** (Ionian → Mixolydian → Dorian → Aeolian → Phrygian → Locrian) and the arrangement changes (kalimba tune + bells → shaker/woodblock → first metal tick → forge hammer + drone → heartbeat + b2 ostinato + distant industry → broken music box). `createMusic(ctx, { dry, wet, seed })` → `{ start, setMood(m, { instant, restSec }), silence, resume, scheduleUntil(t) }`: a lookahead scheduler on an eighth-note grid; melodies are composed per 8-bar phrase (`composePhrase`, seeded `rng`: motif, answer, motif over the third chord, cadence on the tonic; every fourth phrase rests). A mood change fades the current "section" gain (so notes already scheduled go silent), leaves room for the stinger, and starts the new mood on the next bar. `degreeFreq(mood, degree, octave)` gives a note in a mood's scale (used by musical cues).
- `sfx.js` — `CUES`: every effect as a recipe `(kit, t, opts)` with `kit = { ctx, out, wet, mood }`; `CUE_META` sets each cue's rate limit (`gap` ms) and level (balanced from offline loudness measurements). Musical cues (deliver with a climbing `combo`, upgrade, order done, phase stinger) play in the current mood's scale. Specials: `quindarIn`/`quindarOut` (NASA Quindar tones around a CAPCOM transmission), `reveal` (a cheerful jingle that tape-stops into a Phrygian hit), `ending` (timed to the ending's CSS animation: charge, beam 2.6 s, boom 3.2 s, debris, Moon+ ad jingle 6 s, final open fifth 18 s).
- `ambience.js` — `createAmbience(ctx, { out, wet })`: per-mood birds (gone by dusk), crickets at dusk, wind rising each phase, rumble and distant clangs at night, and the **factory hum**, whose level follows the number of working machines and whose pitch sags with `power.throttle` (brownouts are audible).
- `audio.js` — `createAudio()` → the engine: `unlock()` (creates/resumes the `AudioContext` on the first click or key press), the mixer (music and ambience each through a pause lowpass and a duck gain, effects, voice → master → compressor → makeup gain; one shared convolver reverb), `cue(name, opts)`, `update(dt, world)` (per-frame snapshot from `main.js`: mood, paused, throttle, working machines, order status/start, tech count; it detects transitions and cues phase stingers, the reveal, orders, research and brownouts, and muffles music while paused), `onEvents(events)` (deliveries chime), comms hooks for `ui.js` (`lineStart(line, { fresh })` → voice clip length in ms or null, `lineStop`, `commsIdle`), `ending`/`endingSkip`/`afterEnding`, and settings (`settings`, `setSettings`, `toggleMute`; volumes master/music/effects/voice + mute, saved in localStorage `selene.audio.v1`). The tab going hidden suspends the context.
- **Voice:** `voiceLines.js` enumerates every line DELTA (and NILE) can say exactly as `director.js` builds them, and `voiceKey(line)` hashes speaker + mood + text into the clip key (editing a line makes it a new key). `scripts/voice.mjs` records missing lines with ElevenLabs into `public/assets/voice/<key>.mp3` + `manifest.json` (`{ lines: { key: { file, ms, … } } }`), optionally several takes per line into `voice-takes/` (a stopped run resumes without re-recording finished takes) with a `review.html` where you choose a take per line and copy one `pick key n key n …` command; `pick-all [n]` takes take n for every line still without a clip. `try <delta|nile|boss> "<text>"` records any text in a voice into `voice-takes/try/` without touching the game (the `boss` voice, Nolan Isaac Locke, `NIHIL_BOSS_VOICE_ID`, is only used there so far). At runtime `audio.js` loads the manifest; a line with a clip plays through a light EQ (NILE: a PA-system band), ducks music and ambience, and the comms text types along with it and holds until it ends. Lines without a clip stay text-only.
- `soundboard.js` — dev only: open the game with `?sounds` for buttons that play every cue, every music mood and the voice lines.

### `src/brand.js` — SVG art for the HUD
- Design "D · Mission Control" (NASA-style instrument panel in a 70s mission palette; the Claude Design canvas "Nile Brand Directions"). Returns SVG markup strings: `markSVG(evil, size)` (NILE's mark: a three-branch delta in a square frame; NIHIL's: a flat red line), `patchSVG(evil, size, { text })` (the Protocol: Selene mission patch, defaced with a crosshair after the reveal), `deltaSVG(mood)` (DELTA as an oscilloscope badge; its `.trace` path changes per mood and is animated while speaking), `broadcastSVG(evil)`, `memoSVG()`.

### `src/ui.js` — DOM HUD
- `createUI({ root, ...callbacks, getState })` builds the HUD as **plain DOM** panels floating over the full-window 3D view (`root` = `#hud`) and returns `{ update, say, isBusy, showBanner, showTitle, showEnding, toast }`. It is driven entirely through callbacks (`onToolChange`, `onRotate`, `onTogglePause`, `onSpeedChange`, `onSave`, `onLoad`, `onUnlock`) and a `getState()` pull function — it reads no game state directly. Panels: **top bar** (`.topbar`: company mark + name, credits readout, power gauge of `SEGMENTS` cells, sim controls, Save/Load/Keys; `.help` popover), the **phase ribbon** (`.ribbon`, top centre; `showBanner` turns it into a bigger `.celebrate` ribbon for a few seconds), the **console** (`.console`, left: mission patch + phase, requirement bars + next unlocks — rebuilt when the phase changes —, the "Flight plan" objectives, Research (hidden until the Lab is unlocked), Priority Request (hidden before phase 2)), the **keys** (`.keys`, bottom: one hardware key per `BUILD_DEFS` entry with its hotkey, the machine's picture from `icons` (an SVG glyph as fallback) and cost; locked ones stay pictured but greyed with a lock badge and show the phase they arrive in, `PH 02`; the upgrade/demolish/rotate keys are pictured the same way, a size smaller), and the **tooltip** inspector that follows the hovered cell (`getState().hoverScreen`, from `renderer.projectCell`): what a machine takes and makes (`hoveredIO`), what it holds, and how it is hooked up (`hoveredPorts`: output not connected / blocked, how many input sides are fed). The Keys popover has a legend for the port arrows. `body.evil` (phase ≥ 4) re-points the CSS tokens to alarm red and `body[data-phase]` drives the sky.
- **Comms panel** (`.comms`, bottom right, DELTA's CAPCOM terminal): a message queue with time-based typewriter text, a linger time scaled to line length, click to finish/skip, and a Log of the last lines. With a voice clip (`sound.lineStart` returns its length) the text types along with it and the line holds until the voice ends; the first click finishes the text, the second skips (and stops the voice). Toasts float above the keys; title screen and ending are full-screen overlays.
- **Juice:** the credits readout counts toward the real value and flashes mustard (earned) or red (spent); a requirement row bumps on each delivery and gets a ✓ when met; a hotkey presses its key in; a newly ticked objective pops (with a `check` cue); DELTA's portrait pops on each line; a completed phase flashes the screen edges (`.phase-flash`); the power gauge blinks in a brownout.
- **Ending** (`showEnding({ stats, onContinue, onNewGame, stage })`): plays in the world on the `END` timeline (seconds): `body.cinematic` hides the HUD and letterbox bars slide in (caption + countdown clock on top, subtitles at the bottom); `stage.start()` (renderer `frameCannon`) returns where the Moon should hang and the HUD moves the CSS Moon there (`--moon-x/y` on `#view`) under the cut; the countdown charges the cannon; at `fire` a DOM beam runs from the muzzle to the Moon; at `hit` the Moon breaks into CSS shards under a white flash and the sky cuts to the aftermath (`skyOverride` held it at 4 until then); at `ad` the **Moon+ billboard** (`.moonplus`, a DOM element behind the canvas at the Moon's position, shown by CSS whenever `body[data-phase="5"]`, so it stays in the sandbox sky) flickers on; DELTA's last lines run as subtitles; then the **mission report** (`.report`, console style: stats, Keep building / New contract). A click anywhere skips to the report. Comms lines are held while it plays (`isBusy()` is true). All its text is in `story.js` `ENDING`.
- **Sound:** an optional `sound` object (the `audio.js` engine) gets told what happens in the HUD (comms lines, panels opening, the ending, a tech that can't be bought); the top bar's **Sound** popover (`.sound-panel`) has master/music/effects/voice sliders, a mute toggle and how many voice lines are recorded.

### `src/main.js` — orchestrator
- Thin wiring layer: calls `initGrid()`, `await createRenderer(#view)` (with a loading line), `createAudio`, `createUI`, `createDirector`, `startGameLoop`, and translates input into grid edits and camera moves: pointer events on the canvas use `renderer.pickCell`; left builds, right/erase drags erase, middle-drag pans, wheel zooms, WASD/arrows pan, Q/E rotate the view. Belts are drag-laid (`placeBelt`); a diagonal mouse jump is walked as an L so belts stay connected. Owns the transient `state` (tool, dir, paused, started, speed, hovered, build pulse, drag, focus) that does **not** belong in the simulation. Tools: `belt | splitter | merger | extractor | smelter | assembler | generator | lab | upgrade | erase` (keys `1`–`4` belt/extractor/smelter/assembler, `5` upgrade, `6` erase, `7`/`8` splitter/merger, `9` generator, `0` lab, `R` rotates, `Space` pauses, `M` mutes); `selectTool` refuses locked buildings with a toast.
- Owns the **sound wiring**: unlocks audio on the first gesture, cues the player's actions (tool keys, build by machine size, belt segments, demolish, upgrade, denied actions, rotate, pause, speed), passes each tick's events to `audio.onEvents`, and sends `audio.update` a world snapshot every frame (`snapshot()` also counts `working` machines for the factory hum).
- Owns the **campaign flow**: title screen (new / resume) → play → ending (`ui.showEnding` with a `stage` wired to the renderer's ending API; `state.cinematic` blocks input meanwhile) → sandbox. Builds the world `snapshot()` for the director (polled every 200 ms while `state.started`) and copies the first open objective's `focus` into `state.focus` for the renderer.
- Owns **order policy**: `issueOrder()` picks random `target`/`ticks`/`reward` from the `config.js` `ORDER_*` ranges; a per-frame `tickOrders()` watcher issues the first order once phase 1 is done and auto-cycles a new one `ORDER_GRACE_TICKS` after the previous resolves.
- Owns **persistence** (localStorage key `lifeline.save.v2`, the pre-rename key kept so existing saves still load): `saveGame()` JSON-stringifies `{ ...serialize(), story: director.save(), visual: renderer.saveVisual() }` (autosave every 60 s, on each phase change and on `beforeunload`; never before a campaign starts); `loadGame()` parses, calls `loadState()`, then `renderer.reset()` + `renderer.loadVisual(data.visual)` + `renderer.applyEvents(events, 0)` to rebuild sprites and paving, clears transient drag/hover and restores the director. If the 3D assets fail to load, the loading line says so instead of hanging. Both are wrapped in try/catch and return a boolean for the UI status line.

### `src/config.js` — tunables
`GRID_WIDTH` × `GRID_HEIGHT` (32 × 24), `TICK_RATE`; map layout (`PAD_POS`, `CANNON_AREA`, `ORE_FIELDS` blobs — `initGrid()` rasterises them with a deterministic `cellHash` edge, so terrain is identical on every load); economy (`STARTING_MONEY`, `PRODUCT_REWARD`, `MACHINE_COST`, `UPGRADE_COST`, `MAX_TIER`); processing (`PROCESS_TICKS` = ticks-per-op per tier, `BUFFER_CAP`); and orders (`ORDER_TARGET`, `ORDER_TICKS`, `ORDER_REWARD` are `[min, max]` ranges, `ORDER_GRACE_TICKS`). Grid is indexed `grid[x][y]`; one cell is one world unit in the 3D view.

### Layout
`index.html` has `#app` → `#view` (full window: six `.sky` layers crossfaded by `body[data-phase]`, which `ui.js` sets; the transparent Three.js canvas; `#loading`) + `#hud` (the overlay `ui.js` builds into; `pointer-events: none` except on its panels, so the canvas gets every click between them). Styled in `src/style.css`: design tokens on `:root` (midnight, paper, signal orange, mustard, teal; `body.evil` swaps signal/sunset/teal to alarm red), square corners and 1 px hairlines. Fonts are self-hosted via `@fontsource` (imported at the top of `main.js`, all OFL): **Big Shoulders Display** for mission headlines, **Archivo** (variable, with width axis) for the brand and body text, **IBM Plex Mono** for telemetry and labels. Static assets live in `public/assets/kenney/{factory,city,space,nature}/` with each pack's `License.txt`.

## Conventions

- Coordinates are always `(x, y)` with `x` as the column. Keep the boundaries clean: simulation logic, recipes, and economy in `grid.js`/`config.js` (returning events), 3D drawing in `renderer.js` (+ `assets.js`, `environment.js`, `camera.js`), loop timing in `gameLoop.js`, DOM HUD in `ui.js`, input/wiring in `main.js`, campaign data in `campaign.js`, every player-facing string in `story.js`, story timing in `director.js`.
- **Sprite/event invariant:** an item has a sprite only between its `spawn` and `consume` events. Anything that destroys an in-transit item (e.g. `removeMachine`) must emit a `consume` so the sprite is cleaned up; items absorbed into a machine buffer are `consume`d on entry. On load this means **only `cell.item` is re-spawned** — never buffer contents or `pendingOutput`.
- **Economy invariant:** `STARTING_MONEY` must cover bootstrapping one full ore→product chain, and `PRODUCT_REWARD` must make a running chain net-positive, or the game stalls.
- To add a **machine type**: add it to `MACHINE_COST` (+ `PROCESS_TICKS` if it processes), handle it in `cellAccepts` + the relevant `updateFactoryLogic` phase, give it ports in `portsFor` (+ `machineIO`) (processor → `PROCESSORS`/`UPGRADABLE`; pure router → the movers phase), give it a case in `buildView` (renderer; add any new models to `MANIFEST` in `assets.js`), add a key to `BUILD_DEFS` (+ an `ICON` path) in `ui.js` and a hotkey in `main.js`. Machines serialize automatically as long as they stay plain data.
- To add an **item type / recipe**: add a mesh case to `createItemMesh` (assets), `ITEM_NAMES` (story) and the `SMELT`/`ASSEMBLE` tables + `recipeFor` (grid).
- To add a **story beat**: append to `BEATS` in `story.js` (list order = play order). Guard tutorial beats with conditions that turn false once the player is past that step, so they're skipped instead of arriving late.
- Machine types also need an entry in `BUILDING_NAMES`/`BUILDING_DESC` (story) and, if gated, a phase's `unlocks` (campaign).
- **Save format:** machines are stored as-is, so keep them plain JSON-able; `loadState` overlays saved fields onto `makeMachine` defaults, so adding a new machine field is backward-compatible. Bump `SAVE_VERSION` only for breaking changes.

## Verifying changes

There are no automated tests. Playwright (a devDependency) is available to drive the game in a real browser — `verify-flow.mjs` is a working example (`node verify-flow.mjs` with the dev server on :5173). Launch Chromium with `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`, or headless WebGL renders blank. A script must clear `localStorage`, wait for **Begin Onboarding** (it appears once the models have loaded) and click it, then get cell positions from `window.__renderer.projectCell(x, y)` (the HUD panels sit on top of the canvas, so pick cells that aren't under the console, keys or comms) (page coordinates of a cell centre; move the camera with `window.__renderer.rig`). In dev builds `window.__sim` (the live `grid.js` module), `window.__campaign` and `window.__renderer` expose the real instances — e.g. `window.__sim.project.phase = 1` skips the first gate (a phase jump plays the completion juice: camera shake + zoom punch, so wait for the view to be still before clicking cells, as `verify-flow.mjs` does). Don't `import('/src/grid.js')` from the page: Vite's HMR timestamps can hand you a second, empty module instance (stateless modules like `synth.js`/`music.js`/`sfx.js` are fine to import, e.g. to render sounds on an `OfflineAudioContext` and measure peak/RMS). `window.__audio` is the live sound engine: `log` lists the cues played, `context`, `mood`, `speaking`, `musicDuck`. Avoid clicking cell `(0,0)` just to focus the page — that places a belt.
